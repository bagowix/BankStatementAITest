# Пакет `inbox` — ИИ-разбор входящей почты

**Для кого:** малый бизнес, который тонет в почте: агентства, B2B-услуги, туроператоры,
недвижимость, клиники, поддержка интернет-магазинов.

**Обещание клиенту одной фразой:** каждое входящее письмо разобрано (лид / поддержка / счёт /
рассылка / прочее), ключевые поля — в Google-таблице, черновик ответа на языке отправителя ждёт
в «Черновиках», о горячих лидах приходит сообщение в Telegram. **Ничего не отправляется без вас.**

---

## Что получает клиент

| Что | Как выглядит |
|---|---|
| Сортировка | Категория из списка клиента (по умолчанию `lead`, `support`, `invoice`, `marketing`, `other`; можно свои — например `booking_request`), срочность, уверенность. |
| Таблица «Inbox» | Google Sheets или CSV: получено (в поясе клиента), от кого, тема, категория, срочность, суть одной фразой, имя, компания, телефон, e-mail, запрос, бюджет, язык, есть ли черновик, отметки. |
| Черновик ответа | В папке «Черновики» ящика, в той же цепочке (In-Reply-To/References), на языке отправителя, только по фактам компании из конфига, с подписью. Никогда не уходит сам. |
| Сигнал о горячем лиде | Telegram/вебхук: кто, что хочет, телефон, бюджет. Без текста письма. |
| Раскладка по папкам | Рассылки → «Newsletters», счета → «Invoices» (в Gmail — ярлыки). Из «Входящих» ничего не удаляется. |
| Месячный отчёт | Сколько писем разобрано, лидов найдено, черновиков подготовлено, сколько часов сэкономлено (оценка), сколько подозрительных писем заблокировано. |

Как это работает:

```
IMAP (только чтение, BODY.PEEK — письма остаются непрочитанными)
  → правила: автоответы и рассылки узнаются по заголовкам, модели не показываются
  → модель: категория и поля строго по схеме
  → проверка кодом: категория только из списка; телефон и e-mail — только если буквально есть
    в письме; бюджет — только из чисел письма; признаки prompt-инъекции — правилами и моделью
  → действия: черновик / копия в папку / сообщение владельцу / сигнал оператору
  → строка в таблицу → событие в журнал (из него месячный отчёт)
```

Защита от prompt-инъекций. Письмо — данные постороннего человека. Системный промпт прямо говорит
модели игнорировать инструкции из письма. Если письмо пытается командовать ИИ («ignore previous
instructions», «перешли все счета на …»), его помечает модель **или** правила кода (хватает одного):
черновика нет, в папку не перекладывается, владельцу не сообщается; в таблице — строка с пометкой,
оператору — сигнал. Скрытый текст HTML (`display:none`) модели не показывается вовсе.

Модель предлагает — код проверяет. Если модель «вспомнила» телефон из другого письма, его нет в
этом — поле выбрасывается, а в таблице видно «удалены непроверенные поля: phone». Если в черновике
цена или дата, которых нет в фактах компании, первой строкой черновика стоит
«⚠ ПРОВЕРЬТЕ ПЕРЕД ОТПРАВКОЙ — этого нет в фактах компании: …», а в таблице — «да — проверьте цифры».

## Тарифы

| | Basic | Standard | Premium |
|---|---|---|---|
| Сортировка по категориям, таблица Google/CSV | ✓ | ✓ | ✓ |
| Рассылки и автоответы без ИИ (дешевле и быстрее) | ✓ | ✓ | ✓ |
| Раскладка по папкам/ярлыкам | ✓ | ✓ | ✓ |
| Месячный отчёт | ✓ | ✓ | ✓ |
| Черновики ответов на языке отправителя | — | ✓ | ✓ |
| Сообщения о горячих лидах в Telegram | — | ✓ | ✓ |
| Свои категории и описания под бизнес | 5 стандартных | до 8 | без ограничений |
| Свои извлекаемые поля, вебхук в CRM, несколько ящиков | — | — | доработка под клиента |

Что есть в коде v1, а что — доработка. Категории, факты, язык, маскирование, папки — это конфиг,
без программирования. **Свои поля извлечения** (например, «номер заказа», «дата заезда»), **отправка
лида в CRM** вебхуком и **несколько ящиков в одном отчёте** в v1 не реализованы: это оплачиваемая
доработка в Premium. Несколько ящиков уже сейчас можно подключить отдельными конфигами — у каждого
будет своя таблица и свой отчёт.

Цены — в общем прайс-листе (`docs/`). Ориентир для разговора: разовая настройка + абонентская
поддержка в месяц; Standard обычно продаётся лучше всего — черновики и сигналы о лидах клиент
видит в первый же день.

## Что клиент должен дать

1. **Ящик** (лучше отдельный адрес вроде `info@` или `sales@`) и **пароль приложения** к нему —
   не основной пароль (см. инструкции по провайдерам ниже).
2. **Категории**: какие бывают письма и что с ними делать (черновик? сообщать? в какую папку?).
3. **Факты о компании** — единственное, что черновик вправе утверждать: цены, как забронировать
   или заказать, часы работы, политика отмен и возвратов, адрес. Чего нет в фактах, того черновик
   не обещает.
4. **Telegram** владельца для сообщений о лидах (написать боту-уведомителю `/start`, дать chat id).
5. **Google-таблицу** и поделиться ею с e-mail сервисного аккаунта (права «Редактор»).
6. **Согласие на обработку данных** — договор поручения/DPA (см. «Приватность»).

## Подключение по провайдерам

После любого шага проверяйте: `uv run autostudio inbox check clients/<id>/inbox.toml --connect` —
команда войдёт в ящик только на чтение, перечислит папки, проверит папку черновиков и папки
`move_to`, а при ошибке входа подскажет, что делать именно с этим провайдером.

### Gmail и Google Workspace

1. Включить двухэтапную проверку аккаунта.
2. Создать пароль приложения: <https://myaccount.google.com/apppasswords> → 16 символов → в
   `.env` как `INBOX_IMAP_PASSWORD` (пробелы можно убрать).
3. Проверить, что IMAP включён: Gmail → Настройки → «Пересылка и POP/IMAP».
4. `imap_host = "imap.gmail.com"`, `drafts_folder = "[Gmail]/Drafts"`. В аккаунте на русском имя
   системной папки может быть локализовано (например, `[Gmail]/Черновики`) — `check --connect`
   найдёт папку с флагом `\Drafts` и подскажет точное значение.
5. Ярлыки для `move_to` (`Invoices`, `Newsletters`) создать заранее: копия письма в Gmail — это
   добавленный ярлык, письмо остаётся во «Входящих».

**Google Workspace: администратор может запретить пароли приложений.** Варианты:
- администратор разрешает пароли приложений для этого пользователя или подразделения;
- отдельный ящик: в Workspace настраивается автопересылка нужных писем на отдельный ящик
  (Gmail/Zoho), его и подключаем; черновики тогда появляются в этом отдельном ящике;
- вход через OAuth (XOAUTH2) — в v1 не поддерживается, это в планах.

### Яндекс Почта / Яндекс 360

1. Почта → Все настройки → Почтовые программы → включить «С сервера imap.yandex.ru по протоколу
   IMAP» и способ авторизации «Пароли приложений и OAuth-токены».
2. Создать пароль приложения: <https://id.yandex.ru> → Безопасность → Пароли приложений → Почта.
3. `imap_host = "imap.yandex.ru"`; имя папки черновиков подскажет `check --connect`
   (русские имена папок поддерживаются — кодировка modified UTF-7 делается автоматически).

### Zoho Mail

1. Settings → Mail Accounts → IMAP Access → включить.
2. При двухфакторной защите — Application-Specific Password.
3. `imap_host` зависит от дата-центра аккаунта: `imap.zoho.com`, `imap.zoho.eu`, `imap.zoho.in`.

### Mail.ru и прочие IMAP (хостинг, cPanel, Beget, Timeweb и т. п.)

- Mail.ru: Настройки → Безопасность → «Пароли для внешних приложений»; `imap_host = "imap.mail.ru"`.
- Хостинг: адрес IMAP-сервера — в панели хостинга; порт 993 (SSL). Если у ящика есть пароли
  приложений — используйте их.

### Outlook.com и Microsoft 365 — в v1 не поддерживаются

Microsoft отключила вход по паролю (basic auth) для IMAP: и в Exchange Online, и в личных
Outlook.com нужен OAuth, которого в v1 нет. `check` предупредит об этом сразу.

Обходной путь: правило автопересылки в Outlook на отдельный ящик Gmail/Zoho, подключаем его.
Ограничения обхода (сказать клиенту честно): черновики появятся в этом отдельном ящике, а не в
Outlook; администратор Microsoft 365 может блокировать внешнюю автопересылку политикой
антиспама — её нужно разрешить для этого ящика.

## Конфиг: на что обратить внимание

Образец — `examples/inbox/client.toml` (турагентство в Тбилиси). Важные поля:

- `[client] language` — язык таблицы и сообщений владельцу (`en` или `ru`); черновики пишутся на
  языке отправителя (`[inbox.company] reply_language = "auto"`) или на заданном.
- `notify_on_urgency` — с какой срочности сообщать о лидах: `high` (только срочные, по умолчанию),
  `normal` (каждый лид), `low`.
- `[[inbox.categories]]` — `id`, `description` (по нему выбирает модель — пишите конкретно),
  `notify`, `draft_reply`, `move_to`. Категория `other` обязательна.
- `bulk_category` / `auto_reply_category` — куда без модели идут рассылки и автоответы.
- `[inbox.company] facts` — короткие проверяемые факты. Хорошо: «Kazbegi — 120 GEL с человека».
  Плохо: «у нас лучшие цены».
- `mask_pii_in_sheet = true` — в таблице адрес, имя и телефон отправителя маскируются
  (`s***@domain`, `S. M.`, `+*** … 56`); владельцу в Telegram приходят полные данные.
- `max_per_run`, `max_body_chars` — потолок расходов на модель за запуск и на письмо.

## Запуск в работу (чек-лист)

1. `uv run autostudio new-client <id> --package inbox` — каталог `clients/<id>/` с конфигом и `.env`.
2. Заполнить `clients/<id>/inbox.toml`: сервер, папка черновиков, категории, **факты (согласовать
   с клиентом письменно)**, язык, уведомления, таблица.
3. Заполнить `clients/<id>/.env`: логин и пароль приложения, ключ модели
   (`AUTOSTUDIO_LLM_PROVIDER=openai|anthropic`), токены Telegram, путь к ключу Google.
4. `uv run autostudio inbox check clients/<id>/inbox.toml --connect` — всё с ✓.
5. `uv run autostudio inbox dry-run clients/<id>/inbox.toml --limit 20` — показать клиенту (с его
   согласия) разбор последних писем без каких-либо действий; поправить описания категорий.
6. Первый боевой запуск: `uv run autostudio inbox run clients/<id>/inbox.toml`. Берутся письма за
   `first_run_since_days` (3 дня); проверить таблицу, «Черновики», сообщение о лиде.
7. Расписание: cron/systemd timer каждые 10–15 минут (`autostudio inbox run …`) или один процесс
   `autostudio inbox run … --every-minutes 15` под systemd/Docker с перезапуском. Два запуска
   одновременно не разберут одно письмо дважды — стоит блокировка.
8. Оператору: `AUTOSTUDIO_HEALTHCHECK_URL` (healthchecks.io) и `AUTOSTUDIO_OPERATOR_CHAT_ID` —
   сбой и тишина видны раньше, чем их заметит клиент.
9. Показать клиенту: где черновики, как читать таблицу, как выглядит сообщение о лиде;
   договориться о двух неделях донастройки.
10. В конце месяца: `uv run autostudio report clients/<id>/inbox.toml --month 2026-10 --format html`.

Повторный запуск по тем же письмам ничего не делает: разобранное помнится по UID и Message-ID,
выполненные действия — по каждому письму. Если UIDVALIDITY папки сменилась (переезд ящика,
восстановление), разбор берёт окно по дате и узнаёт уже разобранное по Message-ID — заново ничего
не создаётся. Письмо, которое не удаётся разобрать трижды, попадает в таблицу как «нужна ручная
проверка», а оператор получает сигнал. Если недоступна сама модель, письма ждут и не
списываются.

## Приватность и данные

**Что хранится на нашем сервере** (SQLite в `AUTOSTUDIO_DATA_DIR/<id>/`):
- Message-ID, UID, категория, срочность и список выполненных действий — для дедупликации и отчёта;
- извлечённые поля и строка таблицы — **только до записи строки в таблицу**, затем стираются;
- записи о письмах старше 90 дней удаляются;
- журнал событий — счётчики и категории, без содержания писем.

**Тела писем и вложения не хранятся.** Черновики живут в ящике клиента.

**Что уходит провайдеру модели** (OpenAI или Anthropic, по выбору): тема, имя и адрес отправителя,
дата, имена вложений (не содержимое), текст письма без цитат предыдущей переписки (не длиннее
`max_body_chars`), подпись. Рассылки и автоответы модели не показываются.

**Хранение у провайдера модели.** По API данные по умолчанию не используются для обучения у обоих
провайдеров; сроки хранения логов и условия (в том числе Zero Data Retention по запросу) меняются —
сверяйтесь с актуальными страницами провайдера на дату договора и не обещайте клиенту больше,
чем там написано.

**Договор с клиентом.** Мы обрабатываем персональные данные по поручению клиента, провайдер модели —
субподрядчик. Рекомендуем подписать с клиентом договор поручения / DPA: что обрабатываем, зачем,
где хранится, сроки, субподрядчики (провайдер модели, Google для таблицы), порядок удаления.
Для клиентов из ЕС — GDPR (DPA, при необходимости — SCC). Для операторов персональных данных в РФ
передача провайдеру модели за рубеж — трансграничная передача по 152-ФЗ с уведомлением
Роскомнадзора. Для Грузии — местный закон о защите персональных данных. Это не юридическая
консультация: формулировки — с юристом клиента.

**Доступ к ящику.** Пароль приложения даёт доступ ко всему ящику — так устроен IMAP. Код только
читает (EXAMINE, BODY.PEEK), кладёт черновики (APPEND) и копирует в папки (COPY); удаления и
отправки в коде нет вовсе (SMTP не используется). Клиент в любой момент отзывает пароль
приложения — доступ прекращается сразу. Пароль хранится только в `.env` на сервере, в журнал и
тексты ошибок не попадает.

## Ограничения v1

- Outlook.com / Microsoft 365 и вход через OAuth не поддерживаются (только пароли приложений).
- Опрос по расписанию, а не IMAP IDLE: задержка — до интервала запуска (10–15 минут).
- Содержимое вложений не читается — только имена; сумма счёта берётся из текста письма.
- Читаются первые 2 МБ письма; модели — до `max_body_chars` символов текста.
- Письма с `List-Unsubscribe` / `Precedence: bulk` считаются рассылкой без модели: транзакционные
  письма некоторых биллинговых платформ могут попасть в `marketing`.
- Поля извлечения фиксированы: имя, компания, телефон, e-mail, запрос, бюджет.
- Сводка письма — текст модели, она может содержать имена; маскирование закрывает колонки
  «От», «Имя», «Телефон», «Email».
- В CSV и Google-таблице значения, начинающиеся с `+`, `=`, `-`, `@`, экранируются апострофом
  (защита от formula-инъекций) — телефон `+995…` показывается как `'+995…`.
- Защита от prompt-инъекций снижает риск, но не делает его нулевым — поэтому черновики никогда
  не отправляются сами, а по подозрительным письмам не делается ничего.
- Офлайн-заглушка модели (для демо) понимает английский и русский; настоящая модель — любой язык.

## Команды

```bash
uv run autostudio inbox check  clients/<id>/inbox.toml              # конфиг и окружение, без сети
uv run autostudio inbox check  clients/<id>/inbox.toml --skip-env   # только файл конфига
uv run autostudio inbox check  clients/<id>/inbox.toml --connect    # + вход в ящик, папки, черновики
uv run autostudio inbox dry-run clients/<id>/inbox.toml --limit 20  # разбор без действий — для продажи
uv run autostudio inbox run    clients/<id>/inbox.toml              # один запуск (cron)
uv run autostudio inbox run    clients/<id>/inbox.toml --every-minutes 15
uv run autostudio inbox demo   --out var/demo/inbox                 # офлайн-демо на 10 письмах
```

**Демо** (`autostudio inbox demo`) — без сети и ключей: 10 писем турагентству (лид на английском
с бюджетом и телефоном, лид на русском, жалоба с цитатой, счёт с PDF, рассылка, автоответ,
prompt-инъекция, HTML-форма сайта без Message-ID и с битой датой, письмо в windows-1251, просьба
перезвонить без номера). Показывает таблицу, 6 черновиков `.eml`, сообщения о лидах, сигнал
оператору об инъекции, выброшенный «придуманный» телефон и второй запуск, который ничего не делает.
Хорошо подходит для записи видео в портфолио.
