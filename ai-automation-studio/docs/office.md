# Офис оператора: счета, книга поступлений, налог 1%, договоры

`autostudio office` — бумаги самого ИП, который продаёт пакеты: счёт прямому клиенту за пару
минут, книга поступлений с курсом НБГ и цифры для месячной декларации малого бизнеса, договор
клиенту из шаблонов `docs/legal`.

> **Это не налоговая и не юридическая консультация.** Правила ниже взяты из
> `docs/research/DECISION_BRIEF.md` (разделы 2 и 6), а там они помечены «не проверено»:
> rs.ge и matsne.gov.ge при подготовке не открылись. Цифры команды `ledger month` — оценка.
> Что и как декларировать, решает бухгалтер. Без его ответа на вопросы из раздела 8 счета
> клиентам не выставляйте (бриф, раздел 6).

## 1. Один раз: `operator.toml` и реестр

```bash
cp operator.example.toml operator.toml   # впишите реквизиты своего ИП
uv run autostudio office init            # создаёт var/office/office.sqlite в корне репозитория
```

Файл профиля в `.gitignore`: репозиторий зеркалируется в публичный, настоящие IBAN и адрес
туда попадать не должны. В git лежит только образец с вымышленными данными. Игнорируются
все файлы `operator*.toml*` в любом каталоге — `operator.prod.toml`, `operator-ge.toml`,
резервные копии `operator.toml~` и `operator.toml.bak`, файлы подкачки редактора
`.operator.toml.swp`. Исключение одно: `operator.example.toml`. Второй профиль называйте
тоже `operator…toml`, иначе он уйдёт в git. Перед коммитом проверьте `git status`: профиля в
нём быть не должно.

В образце заполнены только обязательные поля, и все они — образцы. Необязательные поля
закомментированы. Раскомментируйте только те, что заполните своими данными.

| Поле | Что вписать |
|---|---|
| `legal_name` | `Individual Entrepreneur <Имя Фамилия>` — как в выписке из реестра ИП |
| `legal_name_ru` | `ИП <Имя Фамилия>` для счетов на русском (необязательно) |
| `owner_name` | Имя для договоров (`{{NAME}}`); пусто — берётся `legal_name` без «Individual Entrepreneur» |
| `id_number` | Идентификационный номер ИП (9–11 цифр) |
| `address` | Юридический адрес ИП |
| `bank_name`, `iban`, `swift` | Счёт ИП: банк, IBAN, SWIFT/BIC |
| `email`, `phone`, `website` | Контакты в шапке счёта (`phone`, `website` — необязательно) |
| `telegram` | Username без @ для договоров (`{{TELEGRAM}}`) |
| `bank_address` | Адрес банка — его часто спрашивает банк плательщика за границей (необязательно) |
| `intermediary_bank`, `intermediary_swift` | Банк-посредник (корреспондент) для входящих USD — возьмите в инструкции своего банка для SWIFT-переводов (необязательно) |
| `[payment_note]` | Другие способы оплаты под реквизитами, `en` и `ru`: например, реквизиты Wise ACH для клиентов из США (бриф 2.2: Wise ACH → Wise wire → PayPal) |
| `invoice_prefix` | Префикс номера: `AS-` даёт `AS-2026-001` |
| `default_currency` | `USD`, `EUR` или `GEL` |
| `[tax_note]` | Строка о налогах внизу счёта, `en` и `ru`. Формулировку подтвердите у бухгалтера |
| `[contract_fields]` | Остальные поля `{{…}}` договоров: `SERVER_LOCATION`, `HOSTING_PROVIDER`, `BACKUP_PROVIDER`, `BACKUP_LOCATION` |

При каждом запуске профиль проверяется, и все ошибки выводятся одним сообщением:

- IBAN — форма, длина для страны и контрольная сумма ISO 13616 (mod 97). Опечатка в одной
  цифре или перестановка соседних цифр не пройдут. Образцовый IBAN из `operator.example.toml`
  проверку намеренно не проходит.
- SWIFT/BIC — 8 или 11 символов (и у банка-посредника тоже).
- ID — 9–11 цифр.
- e-mail.
- Остатки образца. Слово «Example» или «Пример» в любом текстовом поле, адреса example.com,
  ID из одной повторяющейся цифры, SWIFT на `XXXX`, Telegram с «example», телефон с семью
  нулями подряд — профиль с такими значениями не загрузится. Скопированный образец, где
  заменили только часть полей, не напечатает чужое имя в счёте или договоре.

Где что лежит. Пути по умолчанию считаются **от корня репозитория** (каталог с
`pyproject.toml` и `operator.example.toml`), а не от текущего каталога. Команда, запущенная
из другой папки, работает с тем же реестром.

| Что | Где | Как переопределить |
|---|---|---|
| Профиль | `operator.toml` в корне репозитория | `--operator <путь>` или `AUTOSTUDIO_OPERATOR` |
| Реестр счетов, книга поступлений, кэш курсов | `var/office/office.sqlite` в корне | `--data-dir` или `AUTOSTUDIO_OFFICE_DIR` |
| Счета (HTML, Markdown) | `invoices/` рядом с реестром | — |
| Договоры | `contracts/` рядом с реестром | `--out` |
| Выгрузки для бухгалтера | `exports/` рядом с реестром | `--out` |
| Шаблоны договоров | `docs/legal` в корне | `--templates` |

Реестр создаёт только `office init`. Остальные команды пустой реестр не заводят. Если файла
нет по пути, который вы указали (опечатка в `--data-dir` или в `AUTOSTUDIO_OFFICE_DIR`),
команда откажется и покажет полный путь, где искала. Так не появится второй реестр, который
снова начнёт с `AS-2026-001`. Полный путь к реестру печатают `invoice`, `ledger add` и
`ledger month`.

Весь `var/` в `.gitignore`. Делайте резервную копию `var/office/` (это один файл SQLite и
документы) вместе с остальными резервными копиями (`docs/OPERATIONS.md`). Если реестр
потеряется, номера счетов придётся восстанавливать по отправленным PDF.

## 2. Счёт прямому клиенту

Прямой клиент — тот, кто платит банковским переводом на счёт ИП, через Wise или PayPal, а не
через площадку. Порядок (бриф 2.2): USD-счёт 1-го числа, оплата в течение 7 дней. Местные
клиенты платят в лари на счёт ИП (бриф 2.1).

```bash
# Разработка и настройка + первый месяц поддержки
uv run autostudio office invoice \
  --client-name "Example Trading LLC" --client-address "1 Example Way, Springfield" \
  --client-email ap@example.org --client-country US \
  --setup 450 --support 99 --period 2026-11

# Абонентская поддержка за месяц, по-русски, в лари
uv run autostudio office invoice --client-name "ООО Пример" --client-country GE \
  --support 250 --period 2026-11 --currency GEL --lang ru

# Своя позиция: "описание;количество;цена" (можно несколько --item)
uv run autostudio office invoice --client-name "Example GmbH" --client-country DE \
  --item "Change request: new booking channel;3;40" --currency EUR

# Из файла: [client], [[items]] (description или preset = "setup" | "support"), currency, language, notes
uv run autostudio office invoice --from-file clients/example/invoice-2026-11.toml
```

Что происходит:

- Номер выдаёт реестр по порядку внутри календарного года: `AS-2026-001`, `AS-2026-002`, …
  Номер не используется повторно, даже если счёт аннулирован. Две команды, запущенные
  одновременно, получат разные номера.
- Номера растут вместе с датами. Команда не выпустит счёт с датой раньше последнего счёта
  серии. Не выпустит и с датой больше чем на 7 дней вперёд или раньше прошлого календарного
  года: опечатка в годе открыла бы новую серию навсегда. Если дата необычная осознанно,
  добавьте `--allow-date`. Номер расходуется навсегда.
- В реестре вместе со счётом хранится снимок ваших реквизитов на момент выпуска: имя,
  адрес, ID, банк, IBAN, SWIFT, строки о налогах и оплате. `invoice show --html` и
  `invoice void` печатают счёт с ними, даже если `operator.toml` с тех пор изменился (новый
  банк, адрес, регистрация НДС).
- `var/office/invoices/AS-2026-001.html` — счёт A4 без внешних шрифтов и картинок. Откройте
  его в браузере и выберите «Печать → Сохранить как PDF». Клиенту отправляйте PDF.
- `AS-2026-001.md` — короткая сводка для письма.
- В счёте есть блок оплаты: получатель, IBAN, банк, SWIFT и назначение платежа. Назначение
  платежа — номер счёта: по нему вы найдёте оплату в выписке.
- Формулировки по умолчанию: «Software development, configuration and integration services» и
  «Technical support and maintenance of software (monthly)». Счёт со словом «consulting» или
  «консультации» команда не выпустит: консалтинг исключён из режима малого бизнеса (бриф 6.2).
  Проверяется каждый текст, который печатается от вашего имени: позиции, `--notes`,
  `[tax_note]` и `[payment_note]`. Имя клиента не проверяется: клиент может называться
  «… Consulting LLC».
- `--support 99 --months 3 --period 2026-11` печатает в позиции диапазон: «— November 2026 –
  January 2027». `--months` — от 1 до 24.
- Суммы считаются в `Decimal`. Цена за единицу — не больше двух знаков после точки. Иначе
  «Кол-во × Цена» в счёте не сойдётся с суммой строки. Каждая строка округляется до центов по
  правилу «половина вверх», итог — сумма строк.
- Если в профиле заданы `bank_address`, банк-посредник или `[payment_note]`, они печатаются в
  блоке оплаты.

Дальше:

```bash
uv run autostudio office invoice list                 # реестр: номер, дата, клиент, сумма, статус
uv run autostudio office invoice show AS-2026-001 --html   # заново сделать файлы
uv run autostudio office invoice void AS-2026-002 --reason "дубль"   # счёт остаётся в реестре с отметкой VOID
uv run autostudio office invoice paid AS-2026-001 --date 2026-11-04 --channel wise
```

`invoice paid` отмечает счёт оплаченным и записывает поступление в книгу. Одна оплата —
одна запись:

- По счёту ещё нет поступлений. Запишется сумма счёта в валюте счёта, страна клиента — тоже
  из счёта. Если клиент заплатил не всю сумму, укажите `--amount` — полученную сумму до
  комиссий.
- Оплата пришла в другой валюте (`--currency GEL` по USD-счёту). Укажите `--amount` —
  сколько пришло в этой валюте. Без него команда откажется: сумму счёта в другую валюту она
  не переводит.
- Оплата уже записана через `ledger add --invoice <номер>`. Тогда `invoice paid <номер>` без
  `--amount` только меняет статус: новой записи нет, дата оплаты — дата последнего
  поступления (или `--date`). Если по счёту пришло меньше суммы счёта, команда об этом
  предупредит. `--amount` здесь — доплата остатка отдельной записью.
- Счёт уже отмечен оплаченным через `invoice paid`. Его поступление **уже в книге**: ту же
  банковскую проводку не записывайте ещё раз через `ledger add --invoice`, иначе удвоятся
  оборот и налог. `ledger add --invoice` по такому счёту — только для остатка частичной оплаты.

Каждая запись по счёту (`invoice paid` и `ledger add --invoice`, при любом статусе счёта)
печатает, сколько по счёту получено против суммы счёта. Запись, похожая на повтор уже
записанной оплаты, не принимается:

- та же сумма, валюта и дата, что у записи по этому счёту;
- в валюте счёта получено бы больше суммы счёта;
- вся сумма уже пришла в валюте счёта, а запись в другой валюте (та же оплата после
  конвертации);
- счёт оплачен, а часть поступлений по нему в другой валюте: без курса суммы не сверить.

Первая запись по счёту не проверяется: повторять ещё нечего. Если клиент правда заплатил
ещё раз или больше счёта, повторите команду с `--extra`. Деньги пришли, значит, это оборот;
сводка покажет переплату.

Порядок с курсом — в разделе 4. Оплаченный счёт не аннулируют: возврат оформляется
отдельно, спросите бухгалтера как.

## 3. Когда счёт НЕ выставлять

- **Upwork и Fiverr.** Счёт клиенту выставляет площадка. Свой счёт или реквизиты вне площадки —
  нарушение её правил (`docs/legal/README.md`, раздел 3). Но поступление в книгу записать
  нужно всегда:

  ```bash
  uv run autostudio office ledger add --date 2026-11-03 --amount 1000 --currency USD \
    --channel upwork --counterparty "Upwork: Example Corp" --country US --fee 100
  ```

  Записывайте сумму **до** комиссии площадки, а дату — день зачисления на баланс площадки.
  Это консервативное правило брифа (6.2): налог считается с валовой суммы. Комиссия (`--fee`)
  хранится только для сведения и из оборота не вычитается. Как правильно, подтвердит
  бухгалтер (вопрос 2 в разделе 8).
- **Клиент оплатил PayPal-инвойсом**, который вы выставили в самом PayPal. Свой счёт можно не
  делать. Поступление запишите с `--channel paypal`.
- **Деньги пришли без счёта**, например перевод от местного клиента по договорённости.
  Запишите поступление через `ledger add`: в оборот идёт каждое поступление, а не только
  оплаченные счета.

## 4. Книга поступлений и курс НБГ

Что записывается в книгу:

- дата получения;
- сумма до комиссий и валюта;
- курс НБГ на дату получения;
- канал;
- плательщик;
- страна клиента — `GE` для грузинского клиента, иначе код страны;
- номер счёта (необязательно);
- комиссия (для сведения);
- заметка.

Курс берётся одним из трёх способов:

1. **`--rate 2.7123`** — вручную, лари за 1 единицу валюты. Работает всегда, курс сохраняется
   вместе с поступлением. В отчёте месяца он помечен «вручную»: сверьте его с официальным курсом.
2. **Автоматически с сайта НБГ**, если `--rate` не задан. Запрос:
   `https://nbg.gov.ge/gw/api/ct/monetarypolicy/currencies/en/json/?currencies=USD&date=YYYY-MM-DD`.
   Курс делится на `quantity`: например, иены публикуются за 100 штук. Ответ сохраняется в кэш,
   и второй раз за тем же курсом команда в сеть не ходит.
3. **В лари** — курс всегда 1.

> **Проверьте формат НБГ при первом настоящем использовании.** Из среды разработки сайт НБГ
> не открылся, поэтому формат ответа взят из описания и не проверен. Перед первой записью
> выполните `uv run autostudio office ledger rate 2026-10-14 --currency USD` и сравните число с
> курсом на nbg.gov.ge за ту же дату. Если не совпадает или команда пишет ошибку, задавайте
> курс вручную через `--rate`. Разбор при любом сбое не угадывает курс, а просит `--rate`.

Дата получения в будущем не принимается. Если НБГ вернёт курс за предыдущий рабочий день
(выходные, праздники), в выводе будет видна его дата. Курс старше 7 дней не принимается.
`--no-fetch` запрещает ходить в сеть.

## 5. Каждый месяц до 15-го: декларация

```bash
uv run autostudio office ledger month 2026-10
uv run autostudio office ledger export --month 2026-10   # CSV для бухгалтера (UTF-8 с BOM — для Excel)
```

`ledger month` показывает:

- поступления месяца с курсами;
- **оборот месяца** и **оборот с начала года** (нарастающим итогом) в лари. По брифу
  декларация подаётся нарастающим итогом, поэтому в форму, скорее всего, идёт оборот с
  начала года. Какую цифру и в какую строку rs.ge вносить, решает бухгалтер (раздел 8);
- **налог к уплате за месяц — оценка**: 1% от оборота с начала года минус 1% от оборота на
  конец прошлого месяца, каждое до тетри по правилу «половина вверх». Так суммы по месяцам
  складываются ровно в налог за год. Для сверки рядом показан простой 1% от оборота
  месяца: он может отличаться на тетри из-за округления;
- доля оборота с начала года от потолка режима 500 000 GEL. На 80% выводится
  предупреждение, при превышении — громкое предупреждение: сумма сверх потолка облагается
  иначе, и оценка 1% тогда занижена;
- **порог НДС**: оборот с грузинскими клиентами за 12 месяцев против 100 000 GEL. Берётся
  самое «тяжёлое» 12-месячное окно, которое заканчивается в этом месяце: порог считается «за
  любые 12 месяцев подряд», а не на конец месяца. Предупреждение — с 80%: после превышения на
  регистрацию плательщиком НДС, по брифу, 2 рабочих дня. Иностранные клиенты в порог не
  включены, бриф считает это вероятным, но не проверенным;
- срок декларации и уплаты — 15-е число следующего месяца.

Порядок:

1. До 5-го сверьте книгу с выписками банка, Wise, PayPal, Payoneer, Upwork, Fiverr: каждое
   поступление записано, даты и суммы до комиссий верны. Выгрузки площадок сохраните.
2. `ledger month` → цифры для декларации; `ledger export` → файл бухгалтеру.
3. Декларация на rs.ge и уплата до 15-го. Подавайте её и в месяц без поступлений: нулевая
   декларация бесплатна и снимает риск (бриф 6.2).
4. Если появилось предупреждение о пороге НДС или потолке — звоните бухгалтеру в тот же день.

## 6. Договоры из шаблонов

Шаблоны в `docs/legal` размечены двумя способами:

- `{{…}}` — ваши поля. Они одни для всех клиентов и берутся из `operator.toml`.
- `[…]` — поля клиента, варианты на выбор и служебные пометки `[LAWYER: …]`,
  `[ACCOUNTANT: …]`, `[VERIFY: …]` (по-русски `[ЮРИСТ: …]`, `[БУХГАЛТЕР: …]`,
  `[ПРОВЕРИТЬ: …]`).

Каждая скобка заполняется по **точному тексту** внутри неё. Если осталось хоть одно
незаполненное место, команда выводит ошибку со списком мест и номерами строк, а файл не
записывает. Договор с пробелами или с пометкой юриста клиенту не уйдёт.

```bash
# 1. Заготовка: все поля шаблона, закомментированные (пустое молча не пройдёт)
uv run autostudio office contract fields service-agreement --lang en \
  --out var/office/clients/example/service-agreement.toml

# 2. Заполните [client], [agreement] и [fields]. Пустая строка "" убирает скобку целиком:
#    вариант не выбран, пометка снята. Другое значение для одного места: "date#2" = "...".

# 3. Сборка (HTML для печати в PDF или --format md для правок)
uv run autostudio office contract service-agreement --lang en \
  --client-file var/office/contract-defaults.toml \
  --client-file var/office/clients/example/service-agreement.toml \
  --drop-review-notes
```

- Можно передать несколько `--client-file`, каждый следующий переопределяет предыдущие. Общие
  решения держите в одном файле: снятые пометки, язык, суд. Файл клиента — отдельно.
- Сведения о клиенте можно задать и флагами: `--client-name`, `--client-legal-form`,
  `--client-country`, `--client-reg-number`, `--client-address`, `--client-representative`,
  `--business-name`, `--number`, `--date`. Любую скобку можно задать через
  `--set "текст в скобках=значение"`.
- `--drop-review-notes` снимает пометки юриста и бухгалтера. Ставьте его только после того,
  как юрист и бухгалтер шаблоны проверили. Пометки `VERIFY` / `ПРОВЕРИТЬ` этот флаг не снимает:
  каждую нужно решить в `[fields]`. Пустое значение ставьте, только когда обещание правда,
  например резервное копирование уже работает (`docs/legal/README.md`, раздел 6). Если
  обещание неправда, удалите пункт в своей копии шаблона и соберите договор из неё:
  `--templates <каталог>`.
- Если одна и та же скобка встречается несколько раз (`[date]`, `[number]`, `[English]`,
  `[Anthropic / OpenAI]`), значение подставляется везде. Команда об этом предупреждает и
  называет строки. Это касается и сведений о клиенте, и ключей из `[fields]` или `--set`.
  Номер Заказа в приложении 1 обычно отличается от номера договора: задайте его как
  `"number#2" = "1"`.
- **Суммы задаются по местам.** В `service-agreement` скобка `[amount]` (`[сумма]`) стоит в
  трёх местах: предоплата 50%, остаток 50% и абонентская плата. Одно значение на все места
  команда не примет. Задайте `"amount#1"`, `"amount#2"`, `"amount#3"`, даже если две суммы
  одинаковые. Заготовка `contract fields` сразу выводит эти ключи по местам.
- Незакрытая `[` в шаблоне — ошибка с номером строки. Иначе пометка юриста без `]` уехала бы
  клиенту как есть. Исправьте копию шаблона и соберите из неё (`--templates`).
- Существующий файл договора команда не перезаписывает. Другой файл — `--out` или
  `--number`, перезаписать — `--force`. Имя файла по умолчанию — номер договора или имя
  клиента. Для кириллических и грузинских имён к нему добавляется короткий хеш, чтобы
  договоры разных клиентов не легли в один файл.
- Договоры с данными клиентов лежат в `var/office/contracts/`, вне git. Подписанные экземпляры
  храните так же (`docs/legal/README.md`, раздел 2).

## 7. Как это проверено

- `tests/office/`: контрольная сумма IBAN, нумерация (по порядку, по годам, без повторов после
  аннулирования, 40 одновременных выдач, даты не идут назад), экранирование текста клиента в
  HTML, суммы только в `Decimal`, разбор ответа НБГ (`quantity = 100`, битые ответы,
  недоступный сайт — через respx), кэш курсов, цифры месяца на учебной книге, налог к уплате
  нарастающим итогом, предупреждение о пороге НДС, договор с пустыми местами → ошибка.
- Ловушки, найденные на ревью, закреплены тестами: `ledger add --invoice` и затем
  `invoice paid` дают одну запись, а не две; обратный порядок, `invoice paid` и затем та же
  проводка через `ledger add --invoice`, отклоняется без `--extra`, и оборот месяца не
  удваивается; доплата через `invoice paid --amount` сверх суммы счёта — тоже отказ; оплата
  в другой валюте без `--amount` — отказ; снимок реквизитов переживает смену банка и адреса; команда из другого каталога
  работает с тем же реестром; копия образца профиля, где заменён только IBAN, не загружается.
- Реальные шаблоны `docs/legal` проверяются тестом: без полей сборка падает с ошибкой, а
  когда заполнена каждая скобка, в результате нет ни `{{`, ни одной служебной пометки. Одна
  сумма на три места в `service-agreement` — отказ. Незакрытых `[` в шаблонах нет.

## 8. Что спросить бухгалтера

1. Строка о налогах в счёте (`[tax_note]`): верна ли «Small Business status holder — VAT is not
   charged» / «Статус малого бизнеса — НДС не начисляется»? Нужно ли писать «not registered for
   VAT»?
2. База 1% для Upwork, Fiverr и PayPal: сумма до комиссии площадки или после? Какая дата
   считается датой получения: зачисление на баланс площадки или вывод на банк? (бриф 6.3, вопрос 2)
3. Курс: официальный курс НБГ на дату получения — так? Что делать с курсовой разницей при продаже
   USD? (вопрос 7)
4. Входят ли в порог НДС 100 000 GEL услуги иностранным компаниям и иностранным частным лицам
   (покупатели на Fiverr)? Сколько дней на регистрацию после превышения? (вопрос 4)
5. Обязательные реквизиты счёта для иностранного и для грузинского клиента: нужен ли
   грузинский язык, подпись, печать, ID клиента? Достаточно ли PDF без подписи?
6. Должны ли грузинские клиенты платить только в лари? Какие документы им дать, чтобы они не
   удерживали 20%? (вопрос 11)
7. Нулевые декларации в месяцы без дохода, штрафы за просрочку (вопрос 5). Какую цифру
   вносить в ежемесячную декларацию: оборот с начала года нарастающим итогом или оборот
   месяца? Налог к уплате — разница 1% нарастающим итогом с прошлым месяцем?
8. Обратный НДС 18% с комиссий площадок, API провайдеров ИИ и хостинга: нужно ли и как его
   подавать? Книга сейчас хранит комиссии только для сведения (вопрос 3).
9. Возврат оплаты или скидка после оплаты: как оформить и как это отражается в декларации?
10. Сколько лет хранить счета, выписки и выгрузки площадок?

## 9. Ограничения

- Курс НБГ из сети не проверен на настоящем ответе: см. раздел 4.
- Возвратов и кредит-нот нет. Оплаченный счёт не аннулируется.
- Частичная оплата: запишите каждую часть через `ledger add --invoice <номер>`, а когда
  пришло всё — `invoice paid <номер>` без `--amount`. Или первая часть — `invoice paid
  --amount`, а следующие — `ledger add --invoice`. Статуса «оплачен частично» нет: после
  `invoice paid --amount` счёт сразу «оплачен». Каждая запись по счёту, при любом его
  статусе, печатает, сколько получено против суммы счёта. Запись сверх суммы счёта
  отклоняется без `--extra` (раздел 2).
- Повтор части оплаты ловится не всегда. Пример: та же часть записана второй раз другой
  датой, и вместе с ней по счёту всё ещё не больше суммы счёта. Такая запись пройдёт, а
  сводка покажет её в «получено». Поэтому сверка с выпиской до 5-го (раздел 5) обязательна.
- Счёт выпускается на английском или русском. Грузинского шаблона нет.
- Снимок реквизитов есть у счетов, выпущенных этой версией. Счёт из реестра без снимка
  печатается с текущим `operator.toml`, и команда об этом предупреждает.
- Сумма сверх потолка 500 000 GEL не пересчитывается по другой ставке, есть только
  предупреждение.
- Обратный НДС не считается.
