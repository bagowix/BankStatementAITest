# Эксплуатация и абонентская поддержка

Абонентская плата — это не «на всякий случай», а конкретная работа, которую клиент видит. Этот
документ описывает, что оператор делает каждый день, неделю и месяц, и как устроены инструменты,
чтобы поддержка 10–20 клиентов занимала часы, а не дни. Цены и состав тарифов — в
`docs/sales/offers.md`.

## Что входит в поддержку (общее для всех тарифов)

| Обязательство | Как обеспечено в коде |
|---|---|
| Сбой замечаем мы, а не клиент | каждый плановый запуск идёт через `supervised_run`: пинг на healthchecks.io (тревога, если пинги прекратились) и сообщение оператору в Telegram с текстом ошибки |
| Отчёт о работе раз в месяц | `autostudio report <конфиг> --month ГГГГ-ММ --format html` строит отчёт только из журнала событий: сколько записей/цен/писем обработано, надёжность запусков, оценка сэкономленных часов с методикой |
| Мелкие правки конфигурации | услуги, часы работы, FAQ, конкуренты, категории писем — правка TOML и перезапуск контейнера, без программирования |
| Починка при изменениях на стороне сайтов/API | `prices probe <url>` показывает, какой способ извлечения цены сломался; селектор правится в конфиге |
| Обновления безопасности | ежемесячно: `uv lock --upgrade`, тесты, пересборка образа, выкладка |

Что **не** входит (оплачивается отдельно по часовой ставке или новым пакетом): новые функции,
новые интеграции, новые каналы (WhatsApp, другой CRM), работа с данными клиента вне пакета.

## Ежедневно (5–10 минут на всех клиентов)

1. Telegram оператора: есть ли сообщения `⚠️ <клиент> / <пакет>: ...`. Нет сообщений — нет сбоев.
2. healthchecks.io: все проверки зелёные. Красная проверка без сообщения в Telegram = процесс не
   запускается вовсе (контейнер упал, сервер недоступен) — смотреть `docker compose ps` и логи.

## Реакция на сбой

1. Прочитать текст ошибки в сообщении оператору — он уже говорит, что сломалось (`LLMError: OpenAI 429`,
   `SinkError: Google Sheets ...`, `ConfigError ...`).
2. Логи: `docker compose -f clients/<id>/compose.yaml logs --tail 200 <пакет>`.
3. Типовые причины и действия:

| Симптом | Причина | Действие |
|---|---|---|
| `LLMError ... 401/403` | ключ провайдера отозван или кончились деньги на балансе | пополнить баланс / заменить ключ в `.env`, перезапустить |
| `LLMError ... 429` | лимит провайдера | разово — подождать; регулярно — поднять тариф провайдера или реже запускать |
| `SinkError ... PERMISSION_DENIED` | клиент закрыл доступ сервисного аккаунта к таблице | попросить клиента снова «Поделиться» с e-mail сервисного аккаунта |
| `selector_not_found` (prices) | сайт конкурента сменил вёрстку | `autostudio prices probe <url>` → новый селектор в конфиг |
| IMAP `AUTHENTICATIONFAILED` (inbox) | клиент сменил пароль Google / отозвал пароль приложения | клиент создаёт новый пароль приложения |
| Telegram `Unauthorized` (booking) | токен бота перевыпущен в @BotFather | новый токен в `.env` |

4. Клиенту — короткое сообщение, если сбой был заметен ему: что случилось, что сделано, что изменили,
   чтобы не повторилось. Честность здесь продаёт продление лучше любого отчёта.

## Ежемесячно (1-го числа)

1. Отчёт каждому клиенту:
   ```bash
   uv run autostudio report clients/<id>/<pkg>.toml --month 2026-10 --format html --out var/reports/<id>-2026-10.html
   ```
   Открыть в браузере → «Печать → Сохранить как PDF» → отправить клиенту вместе со счётом.
2. Счёт за поддержку (PayPal invoice / Payoneer request / через площадку — см. план действий).
   Клиентам с Upwork/Fiverr — только через площадку: вывод клиента за её пределы нарушает правила.
3. Обновления: `uv lock --upgrade && uv run poe check && uv run poe tests`, пересобрать образ,
   выкатить на сервер, проверить `check` каждого клиента.
4. Расходы на модель: токены видны в кабинете провайдера; если клиент стабильно дороже, чем заложено
   в цену, — перейти на более дешёвую модель (`AUTOSTUDIO_LLM_MODEL`) или пересмотреть тариф.

## Резервные копии

Всё состояние клиента — каталог данных (`/data/<client-id>/` в контейнере, том `data`):
журнал событий и SQLite пакетов. Раз в сутки копировать том на другой носитель
(например, `restic` в объектное хранилище). Конфиги и `.env` клиентов хранить в менеджере паролей
или зашифрованном архиве — **не в git**.

## Сервер

Один небольшой VPS (2 vCPU / 4 ГБ) спокойно держит 10–20 клиентов: все пакеты — лёгкие процессы,
тяжёлая работа (модель) — у провайдера.

```bash
# один раз на сервере
apt update && apt install -y docker.io docker-compose-v2 git
git clone <ваш приватный репозиторий> autostudio && cd autostudio
docker build -t autostudio:latest .

# новый клиент
uv run autostudio new-client acme-barbers --package booking   # или локально, затем scp
# заполнить clients/acme-barbers/booking.toml и .env
deploy/new-deployment.sh acme-barbers booking
docker compose -f clients/acme-barbers/compose.yaml run --rm booking booking check /config/booking.toml
docker compose -f clients/acme-barbers/compose.yaml --profile booking up -d
```

## Безопасность

- `.env` клиентов — права `600`, владелец — пользователь, от которого работает Docker.
- Ключи провайдеров моделей — отдельный ключ на клиента (или на группу клиентов), чтобы отозвать
  один, не останавливая остальных, и видеть расход по клиенту.
- Сервисный аккаунт Google — один на оператора; клиент делится с ним только своей таблицей.
- Доступ к серверу — только по SSH-ключу, пароль отключён, `ufw` открывает только 22.
