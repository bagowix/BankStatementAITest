# AutoStudio — упакованная ИИ-автоматизация для малого бизнеса

Три услуги с фиксированной ценой и абонентской поддержкой, которые один разработчик продаёт и
сопровождает из одного репозитория. Каждый клиент получает отдельное развёртывание, отличаются только
его TOML-конфиг и `.env`.

| Пакет | Что получает клиент | Канал |
|---|---|---|
| **booking** | ИИ-бот записи: услуги, свободные слоты, напоминания за 24 и 2 часа, ответы на вопросы только по фактам бизнеса, передача вопроса человеку, журнал в Google Sheets | Telegram (+ WhatsApp Cloud API, Google Calendar — фаза интеграции) |
| **prices** | Цены конкурентов рядом с вашими в одной Google-таблице, сообщение при изменении цены или когда вас обходят | вежливый сбор публичных страниц по расписанию |
| **inbox** | Каждое письмо разобрано: категория, поля, черновик ответа на языке отправителя (никогда не отправляется сам), сигнал о горячих лидах | IMAP по расписанию |

Абонентская поддержка опирается на три вещи из ядра. Журнал событий хранит всё, что пакет сделал
для клиента. Месячный отчёт строится только из этого журнала. Плановые запуски идут под присмотром:
пинг «жив» и сигнал оператору при первом сбое и при восстановлении.

## Быстрый старт

```bash
uv sync                      # окружение со всеми extras
uv run poe check             # ruff format --check, ruff check, pyrefly (preset strict)
uv run poe tests             # тесты и покрытие; ключи провайдеров в тестах обнулены
uv run autostudio demo-all   # офлайн-демо всех пакетов: без сети и ключей
```

Демо по отдельности:

```bash
uv run autostudio booking demo     # сценарий записи: транскрипт, CSV, отчёт в var/demo
uv run autostudio booking chat examples/booking/client.toml   # живой диалог с ботом в терминале
uv run autostudio prices demo      # три магазина, два дня: изменения, обход по цене, сломанный селектор
uv run autostudio inbox demo       # 10 писем: лиды, счета, рассылки, автоответ, prompt-инъекция
```

## Как устроено

- **Модель предлагает, код проверяет.** Ответ модели проходит msgspec-схему. Слоты, цены, телефоны
  и суммы код считает и сверяет сам. Цена из LLM принимается, только если её текст есть на странице.
  Телефон из письма — только если он есть в письме.
- **Текст посторонних — данные, не инструкции.** Письма, реплики и HTML передаются модели как
  данные. Подозрение на prompt-инъекцию блокирует действия и уходит оператору.
- **Без ключа всё работает.** `FakeLLM` с эвристиками пакета обслуживает демо, тесты и запасной режим.
  Если провайдер упирается в лимит расходов или отвечает с ошибкой, `ResilientLLM` переключается на
  эвристики и сообщает оператору.
- **Модель по умолчанию — `claude-haiku-5-5`** с effort `low`, около $1 в месяц на клиента. Другую
  модель конкретному клиенту задаёт одна строка в его `.env`: `AUTOSTUDIO_LLM_MODEL`. OpenAI
  тоже поддерживается и всегда вызывается с `store=false`.
- **Секреты только в окружении.** В конфиге указано имя переменной, значение лежит в `.env`. Логи
  проходят маскировку: токены ботов, ключи, `Bearer`, значения секретов из окружения.

Карта кода, контракт пакета и правила — в [AGENTS.md](AGENTS.md).

## Новый клиент

```bash
uv run autostudio new-client acme-barbers --package booking
# заполнить clients/acme-barbers/booking.toml и clients/acme-barbers/.env
uv run autostudio booking check clients/acme-barbers/booking.toml
deploy/new-deployment.sh acme-barbers booking        # compose-файл клиента на сервере
```

Каталоги `clients/*` и `var/` в git не попадают: в них адреса, чаты, токены и данные клиентов.

## Стек

Python 3.12+, uv + poe, cyclopts 5, dishka, msgspec, httpx, selectolax, aiogram 3, gspread,
protego, phonenumbers, pypdf. Модели — OpenAI Responses API или Anthropic Messages API за одним
протоколом. Проверки — ruff (линт, формат, правила безопасности `S`) и pyrefly в strict-пресете.
Тесты — pytest, respx, порог покрытия 90%.
